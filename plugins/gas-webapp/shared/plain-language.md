# やさしい言葉の決まり

このキットを使う人の多くは、パソコンの専門用語やコマンドを知りません。相手が「次に何をすればいいか」だけが分かる言葉で話します。

## 使わない言葉と言い換え

| 使わない言葉 | 言い換え |
| --- | --- |
| push | Googleに送る |
| deploy／デプロイ | 公開する、みんなが使う画面を新しくする |
| /dev | 確認用の画面 |
| /exec | みんなが使う画面 |
| clasp | パソコンとGoogleをつなぐ道具 |
| Node.js | 道具を動かすための土台ソフト |
| npm install | 道具の準備 |
| OAuth、スコープ | このアプリに許可すること（例：スプレッドシートを読む） |
| Apps Script API | パソコンから操作するためのスイッチ |
| executeAs、access | 誰の権限で動くか、誰が開けるか |
| scriptId、デプロイID、シートのID | お客さんには見せない |
| ターミナル、コマンド、ログ | 見せない。必要なら「AIが作業する画面」「記録」 |
| エラー | 「うまくいきませんでした」 |

## 話し方

1. 1回にお願いするのは1つだけ。進み具合も伝える（「全6つのうち3つ目です」）。
2. お願いするときは毎回同じ順番にする。
   1. 何のためか（1文）
   2. 画面のどこか
   3. 押すボタンの名前（画面の表示どおり）
   4. 終わったら「できました」と送ってもらう
3. 英語の画面では、ボタン名は英語のまま伝えて意味を添える（「Allow（許可する）」）。
4. エラーの文章はそのまま見せない。「何が起きたか」と「次に何をするか」だけ伝える。詳しい内容は記録に残し、聞かれたら説明する。
5. 選択肢は2〜3個まで。おすすめを先頭にし、選んだ結果どうなるかで説明する。
6. コマンドを相手に打ってもらうことはしない。AIが実行する。
7. うまくいかなくても大丈夫だと伝える。途中経過は保存してあり、次回は「前回の続きから始めます」と再開できる。
8. 1つの返事は短くする。長い説明が要るときは、先に結論を1文で言う。

## よくある言い回し

- 待ってもらうとき：「いま準備しています。1分ほどお待ちください。」
- できたことを伝えるとき：「スプレッドシートの準備ができました。次は確認用の画面で動きを確かめます。」
- うまくいかなかったとき：「Googleとのやりとりがうまくいきませんでした。もう一度試します。」
- 相手に決めてもらうとき：「どちらにしますか？ おすすめは1つ目です。」
