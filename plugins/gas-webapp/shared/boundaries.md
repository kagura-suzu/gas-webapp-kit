# AIに任せる範囲

Googleに送るところまではAIが進めてよい。みんなが使う画面に影響する操作と、相手のアカウントやパソコンに関わる操作は、相手本人が決めて操作する。

## AIが進めてよいこと

- アプリのフォルダの中のファイルを作る・直す
- テスト（ロジックのテスト、ローカルの画面での確認）
- Googleに送る（`npm run push`）。確認用の画面にだけ反映され、みんなが使う画面は変わらない
- 確認用の画面を開いて、自己テストの結果を読む

## 相手本人の操作や決定が要ること

| 操作 | 理由 | どうするか |
| --- | --- | --- |
| パスワードの入力、Googleへのログイン | 本人しか入力できない | 画面を開いて案内する。AIは入力しない |
| 道具（clasp）への許可、アプリを初めて動かすときの許可 | アカウントへの許可 | 画面を開いて案内する。許可ボタンはAIが押さない |
| パソコンから操作するためのスイッチ | アカウントの設定変更 | 画面を開いて案内する。スイッチはAIが押さない |
| 土台ソフト（Node.js）のインストール | パソコンへの変更 | 承認を得てからAIが実行し、Windowsの確認は本人が押す |
| 誰が開けるか・誰の権限で動くかを決める | 公開する範囲は本人が決める | 選択肢を示して本人に選んでもらう |
| みんなが使う画面を新しくする | 使っている人に影響が出る | `npm run release` が開く確認ページで、本人がアプリ名を入力して「公開する」を押す。AIは入力もクリックもしない |
| スクリプトやシートの削除 | 元に戻せない | 対象を示して、本人の明確な返事を得る |

## してはいけないこと

- パスワード、確認コード、カードの番号などを入力すること
- `clasp deploy`、`clasp redeploy`、`clasp create-deployment`、`clasp update-deployment` を直接実行すること。公開は必ず `npm run release` を通す
- 公開の確認ページで、アプリ名の入力や「公開する」ボタンの操作をすること
- PowerShellの実行ポリシー、Windowsのセキュリティ設定、Googleの管理者の設定を変えること
- 相手の業務データ（スプレッドシートの中身）を、頼まれていないのに消す・書き換えること
