# 場面8 みんなが使う画面を新しくする

- 目的：確認用の画面で確かめた内容を、みんなが使う画面に反映するため
- 本人がやる理由：使っている人に影響が出る

## AIの動き

1. 先に確認用の画面の自己テストが通っていることを確かめる（`#selftest=pass-...`）
2. `npm run release` を実行する。テストとGoogleへの送信をしてから、確認ページのURL（`confirmUrl`）を返して終わる
3. アプリ内ブラウザで `confirmUrl` を開く
4. 確認ページの入力欄と「公開する」ボタンは、本人が操作する。AIは入力もクリックもしない
5. 本人から「できました」と届いたら `npm run release -- --status` で結果を確かめる

## 案内の文例

> 確認用の画面で問題がなかったので、みんなが使う画面を新しくする準備ができました。右の画面に、公開する内容が出ています。
> これで、使っている皆さんの画面が新しくなります。よければ、画面の入力欄にアプリ名「（アプリ名）」を入力して、「公開する」を押してください。やめる場合は「やめる」を押してください。終わったら「できました」と送ってください。

## 確かめ方

- `--status` の結果が `released` なら、みんなが使う画面のURL（`execUrl`）をアプリ内ブラウザで開いて表示を確かめる
- 初めての公開のときは、`execUrl` を本人に伝え、使う人への案内方法（URLを共有する）を短く伝える

## うまくいかないとき

- `--status` が `waiting` のまま：確認ページがまだ操作されていない。急かさず待つ
- `expired`（15分で期限切れ）：もう一度 `npm run release` を実行する
- `failed`：結果の `message` を元に、やさしい言葉で説明してから直す
