# 場面5 使うスプレッドシートを決める

- 目的：アプリのデータを入れるスプレッドシートを決めるため
- 本人がやる理由：どのシートを使うかは本人しか分からない

## 案内の文例

> アプリのデータを入れるスプレッドシートを用意します。使いたいスプレッドシートはありますか？
> 1. 新しく作る（おすすめ）
> 2. 今あるスプレッドシートを使う

「今あるスプレッドシートを使う」を選んだ場合：

> そのスプレッドシートのURL（ブラウザの上に出ている https://docs.google.com/spreadsheets/... の文字）を、ここに貼り付けて送ってください。

URLが分からない場合は、アプリ内ブラウザで https://drive.google.com/ を開いて：

> 右の画面で、使いたいスプレッドシートを探して開いてください。開けたら「できました」と送ってください。

開いてもらったら、AIがアドレスバーのURLを読み取る。

## AIの動き

- 新しく作る：`npm run create -- --title "<アプリ名>"`
- 今あるシート：`npm run create -- --title "<アプリ名>" --sheet "<URL>"`

## 確かめ方

- 結果のJSONの `sheetUrl` をアプリ内ブラウザで開き、本人に「このスプレッドシートで合っていますか？」と確かめる

## うまくいかないとき

- 権限がない（no-permission）：そのシートを編集できるアカウントでログインしているかを確かめる。持ち主に編集の権限をもらうか、新しく作る方法を提案する
- 本番の大事なデータが入っている：先にシートのコピーを作り、コピーで試すことを提案する（「まずはコピーで試しませんか？ 元のシートには影響しません」）
- 自己テストで「シートの時間帯がアプリと同じ」が失敗した（今あるシートを使った場合だけ起きる）：そのままだと、アプリが書いた日時を読み戻したときにずれる。シートの時間帯を日本にしてもらう。すでにシートに入っている日時の見た目は変わらない

> スプレッドシートの時間帯が日本以外になっていて、このままだとアプリの日時がずれます。右の画面のスプレッドシートで、上の「ファイル」→「設定」を開き、「タイムゾーン」を「(GMT+09:00) 東京」にして「設定を保存」を押してください。押せたら「できました」と送ってください。

- 新しく作ったシートは、最初の読み書きでアプリが時間帯を日本に合わせる（`CONFIG.MATCH_SHEET_TIME_ZONE`。Googleが新しく作るシートはロサンゼルスの時間帯になっていて、試作では日時が8時間ずれた）
