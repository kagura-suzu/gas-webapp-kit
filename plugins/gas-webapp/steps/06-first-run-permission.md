# 場面6 作ったアプリを初めて動かすときの許可

- 目的：アプリがスプレッドシートを読み書きできるようにするため
- 本人がやる理由：アカウントへの許可。一番不安になりやすい場面

## AIの動き

1. `npm run urls` で確認用の画面のURL（`devUrl`）を取得し、`?selftest=1` を付けてアプリ内ブラウザで開く
2. 「承認が必要です」「Review permissions」などの画面が出たら、スクリーンショットで表示を確かめてから案内する
3. 新しい種類の許可（例：Gmailを送る）をコードに足したときは、同じ画面がもう一度出る

## 案内の文例（理由を先に伝える）

> 作ったアプリがスプレッドシートを読み書きするための許可をお願いします。
> 右の画面の「権限を確認」（英語なら Review permissions）を押して、さきほどのアカウントを選んでください。

次に「このアプリは Google で確認されていません」と出た場合：

> いま右の画面に「このアプリは Google で確認されていません」と出ています。ご自分で作ったアプリなので、Googleの審査を受けていないという意味で、危ないものではありません。左下の「詳細」を押して、そのあと「（アプリ名）（安全ではないページ）に移動」を押してください。

最後の画面で：

> このアプリが使う内容（スプレッドシートの読み書きなど）が出ています。一番下の「許可」（英語なら Allow）を押してください。押せたら「できました」と送ってください。

## 英語で出たときの表示

Googleの設定によっては、この場面は英語で出る（試作では英語だった）。案内では日本語の言い方と英語の表示を並べて伝える。

| 日本語の言い方 | 英語の表示 |
| --- | --- |
| 承認が必要です | Authorization needed |
| 権限を確認 | REVIEW PERMISSIONS |
| 確認されていません | (Unverified) / Google hasn't verified this app |
| 詳細 | Advanced |
| （アプリ名）（安全ではないページ）に移動 | Go to （アプリ名） (unsafe) |
| 許可 | Allow |

## 確かめ方

- 画面が自己テストの結果に変わり、URLの最後に `#selftest=pass-...` が付くことを確かめる（結果が出るまで20秒ほどかかることがある）
- 「できました」と言われても同じ許可の画面のままなら、場面0の「非表示になっていたとき」を確かめてから、もう一度お願いする

## うまくいかないとき

- 「このアプリはブロックされています」：会社の管理者の設定。場面9へ
- 何度も同じ許可が求められる：別のアカウントで開いている可能性。アプリ内ブラウザの右上のアカウントを確かめる
